## 一、项目概述

### 1.1 目标

打造一款**跨平台、隐私优先、界面简洁现代**的P2P即时通讯软件，消息与文件全程点对点传输，不经过中心服务器转发，保障用户数据隐私。

### 1.2 支持平台

- Windows

### 1.3 核心特性（MVP版本）

- 点对点文本消息收发
- 好友添加与连接管理
- 本地消息历史存储
- 简洁现代的沉浸式UI设计
- 规划中、尚未实现：点对点文件/图片传输、消息搜索

### 1.4 非目标（MVP阶段不做）

- 群聊功能
- 音视频通话
- 云端消息备份
- 账号注册体系（基于PeerID身份识别）

## 二、技术栈与架构设计

### 2.1 整体技术栈

| 层级     | 技术选型                   | 说明                                    |
| ------ | ---------------------- | ------------------------------------- |
| 客户端UI层 | Flutter 3.x + Dart 3.x | 一套代码编译多端，自绘引擎保证UI一致且美观                |
| P2P核心层 | flutter\_webrtc 插件     | 封装官方WebRTC原生库，提供DataChannel传输与ICE内网穿透 |
| 状态管理   | Riverpod 2.x           | 响应式状态管理，代码结构清晰易维护                     |
| 本地存储   | Hive                   | 轻量级NoSQL数据库，适合存储聊天记录与配置               |
| 信令服务   | Go + Gorilla WebSocket | 轻量高性能，仅用于连接握手，不转发业务消息                 |

## 四、核心功能设计

### 4.1 P2P连接建立流程

1. 客户端A、B分别连接信令服务器，获得唯一PeerID
2. 客户端A输入B的PeerID发起连接请求
3. 信令服务器将请求转发给客户端B
4. B同意后，双方通过信令服务器交换SDP（会话描述协议）信息
5. 双方收集ICE候选地址，通过信令服务器互相转发
6. WebRTC自动选择最优路径建立P2P连接
7. 连接成功后创建DataChannel，所有消息直接点对点传输
8. 信令服务器仅在连接断开时参与重连，不参与业务数据传输

### 4.2 消息协议设计

DataChannel 上传输统一格式的JSON消息：

```json
{
  "type": "text|file|image|system",
  "msg_id": "唯一消息ID",
  "from": "发送方PeerID",
  "timestamp": 1718000000000,
  "content": {}
}
```

### 4.3 UI 设计原则

1. 极简风格：减少冗余元素，突出聊天内容，采用大面积留白
2. 轻量化配色：主色选用低饱和度蓝灰色，背景为纯白 / 纯深灰，避免花哨装饰
3. 圆润柔和：消息气泡、卡片、按钮统一使用大圆角设计
4. 流畅动效：消息发送、页面切换、输入框弹起均加入缓动动画
5. 一致体验：桌面端与移动端保持完全一致的视觉风格与交互逻辑

## 六、环境要求与构建

### 6.1 环境要求
| 工具 | 版本 | 用途 |
|------|------|------|
| Go | 1.22+ | 编译信令服务端 |
| Flutter SDK | 3.2+ (Stable) | 编译 Windows 客户端 |
| Visual Studio Build Tools | 最新版 | Flutter Windows 构建依赖（勾选「使用 C++ 的桌面开发」） |

### 6.2 构建
- go信令服务器：进入 `signaling-server` 目录，执行 `go build -o linkchat-server.exe`
- flutter客户端：进入 `client` 目录，执行 `flutter.bat build windows --release`

### 6.3 运行
1. 启动信令服务：`cd signaling-server && go run .`（默认监听 `:8080`，可用 `PORT` 环境变量修改）
2. 启动客户端：`cd client && flutter pub get && flutter run -d windows`
3. 客户端首次启动默认连接 `ws://localhost:8080/ws`；如需使用自己的服务器，在「设置」页填写信令地址（如 `wss://your.domain.com/ws`）
4. ICE 服务器在 `client/lib/utils/constants.dart` 中配置，默认使用公共 STUN
5. 自检：`flutter test` 与 `go vet ./...` 应全部通过

## 八、安全说明

本项目为学习/MVP 版本，暂不适合用于敏感通信：

- Ed25519 私钥以 base64 明文存放在 Hive 中，尚未接入系统密钥库
- 信令通道默认使用 `ws://`，生产环境请通过 `wss://` 终结 TLS
- 信令服务接受任意 WebSocket 来源，且不做身份鉴权
- 消息未做端到端加密，仅有 WebRTC 自带的传输层保护（DTLS-SRTP）
